# План старта M0: вертикальный срез (обсуждение 2026-09-06)

Статус: M0 в работе. Скелет + BigInt готовы (коммит dc5224e).

## Ключевая идея

Не строить C0 целиком, а провести одну задачу через весь конвейер:
`∫ dx/(x²+1)` от выражения до доказанного ответа. Каждый элемент несущей
конструкции строится в минимальном виде и живёт вечно. Демо-цель посерьёзнее:
`∫ dx/(x⁴+1)` — комплексно-сопряжённые корни, где Риоро обязан дать чистый
вещественный арктангенс вместо комплексных логарифмов (витрина осей
«Качество» и «Доверие» плана на первой же неделе математики).

## Правки плана v0.4 → v0.5 (вызванные «чистым C++» и Numkit)

- D1: C++17 вместо C++20/23 (контракт интеграции).
- D4/D7: FLINT полностью выпадает → собственные слои (`BigInt` → `Q[x]` →
  позже интервальные шары) за фасадами. Пункт о лицензии FLINT в §11 снят.
- D9: однопоточный таймбоксированный каскад; потоки — compile-time опция
  после C1.
- C0 делится на C0a (DAG, числовой слой, полиалгебра, дифференциатор,
  гейт) и C0b (E-graph — отложен до C2; на старте тривиальный выбор
  кандидата с минимальным leaf count).
- Discrimination net Rubi — статические дата-таблицы, не генерация кода
  (бюджет размера WASM). Закрывает один из открытых вопросов §11.

## Порядок работ и статус

1. ✅ Скелет: CMake C++17, gtest через FetchContent, VS 2022, Release+Debug.
2. ✅ `BigInt`: u64-лимбы, знак-модуль, Кнут D на 32-битных разрядах
   (переносимо, без `__int128`/интринсиков), gcd, floor-сдвиги, строки.
   Три слоя тестов + 500k-фаззинг против Python-оракула при разработке.
3. ✅ `Rational` — канонические дроби поверх BigInt. Ключевое решение:
   инварианты (знаменатель > 0, НОД = 1, ноль = 0/1) enforced в единственной
   точке — конструкторе (p, q); вся арифметика проходит через него, поэтому
   любое Rational канонично по построению. Равенство тогда — это прямое
   сравнение пар. Оракул — fractions.Fraction (26 фиксированных векторов) +
   field-аксиомы на 20k итераций + int64-cross-check.
4. ✅ `Expr` DAG + hash-consing + канонический конструктор + принтер
   (core/expr). Решения:
   - `Expr` — тонкий хендл `{Ctx*, id}`; узлы в `std::deque<Node>`
     (адреса стабильны), дети — плоский массив id; равенство = равенство
     id за O(1). Владелец — `Ctx`, никаких глобалов.
   - Канонизация: Add/Mul — flatten + сбор числовых констант + сбор
     лайковых термов (коэффициенты в Add, показатели в Mul, рациональные
     суммы тоже: x^(1/2)·x^(1/2) → x) + сортировка по полному порядку
     compare (Number < Symbol < Pow < Func < Add < Mul). Урок: слияние
     только одинаковых рангов НЕ канонизация — см. баг
     expr-run-merge-noncanonical; клон/перестройка дерева обязана давать
     тот же узел (property-тест — главный страж каноничности).
   - Pow: x^0→1, x^1→x, числовое сворачивание целых степеней (|n|≤65536,
     больше — символически), (u^a)^n→u^(a·n) для целых n, (u·v)^n →
     распределение для целых n. Дробные степени чисел НЕ сворачиваются
     (вещественные ветви — позже, D10).
   - Принтер с precedence-лестницей; дробный Number получает prec 55
     (ниже Pow, выше Mul), база Pow печатается с parentPrec 61, чтобы
     (x^2)^3 ≠ x^(2^3).
5. ✅ Дифференциатор по DAG (core/diff). Решения и уроки:
   - Мемоизация по id узла (fresh map на вызов diff); рекурсия по детям —
     линейно от размера DAG.
   - Pow: три ветки (числовой показатель / числовое основание / общий);
     Func: exp, log, sin, cos, tan, atan (неизвестные — assert/null).
   - Контракт канонической формы: Mul НЕ дистрибутирует над Add (иначе
     комбинаторный взрыв). Следствие: тождество d(a·b) = d(a)·b + a·d(b)
     верно как ФУНКЦИЯ, но не как узел, когда операнд — Mul (n-арное
     правило разворачивается по сплющенным факторам). Property-тесты
     структурной идентичности — только для недистрибутивных операндов;
     функциональные тождества проверит гейт (D(F) − f ≡ 0) позже.
   - Урок о порядке вычислений: аргументы mul({0, pow(0,-1)}) строятся
     ДО сворачивания нуля → патологический pow(0,−1) ассертится. Гарды
     «производная константы = 0» ставятся до построения сингулярных
     узлов (d(log(0)) = 0, d(8^(1/2)) = 0).
6. ✅ `Q[x]` плотный (poly/upoly): арифметика, точное деление, монический
   gcd (Евклид над Q), производная, бесквадратная часть и декомпозиция
   Юна (по монизированному ассоциату, иначе зацикливание на скаляре),
   результант. Решения:
   - Результант — точная Q-Евклидова рекурсия res(A,B) =
     lc(B)^(degA−degR)·res(R,B) со своп-знаком (-1)^(degA·degB).
     Субрезультатантный PRS над Z — апгрейд ПРОИЗВОДИТЕЛЬНОСТИ (рост
     коэффициентов), не корректности; отложен до профилирования
     (техдолг, см. план C1). Слой изолирован в UPoly::resultant —
     замена алгоритма не меняет контракт.
   - gcd монический; squarefreePart определён «до скаляра» — тесты
     сравнивают крест-накрест через lc.
   - Оракул: Python (Fraction-Евклид, 30 векторов gcd+res) + сильные
     тождества: res(A, x−r) = A(r), мультипликативность по обоим
     аргументам, знаковая симметрия; Юн: lc·∏F_i^i = A.
   - Урок тестирования: случайные факторы НЕ бесквадратны и НЕ взаимно
     просты — строить тестовые произведения надо после явной нормализации
     (squarefreePart + деление перекрёстных gcd).
7. ⬜ Эрмит → Трагер → Риоро (срез).
8. ⬜ Гейт Tier-1 + property-тесты 10k случайных рациональных функций.

## Решения недели 1 (потом не переиграть)

- Канонизация в конструкторе — единственный контракт всего выше:
  авто-упрощение (`x·1→x`), сортировка детей AC-операторов, числовое
  сворачивание. Детерминизм важнее качества формы; качество — потом
  E-graph'ом (C0b/C2).
- Владелец интернера — `Ctx`, никаких глобальных таблиц (потоки, снапшоты).
- Бюджет/отмена с первого дня: каждый алгоритм принимает `Budget&`.
- Парсер отложен: тесты строят выражения кодом.

## Definition of Done среза

Property-тест: 10 000 случайных рациональных функций → интеграл →
`D(F) − f ≡ 0` символьно → 100% `PROVED_SYMBOLIC`. Это заготовка будущего
CI-корпуса §7.
