# Отладка деления BigInt: метод и уроки (2026-09-06)

Три бага найдено и починено в день написания; детали репро — в
`bugs/closed/num/`. Здесь — переносимая методика, которая их поймала.

## Симптом → изоляция

Симптом: зависание тестового процесса. Изоляция за три шага:
(1) запуск exe напрямую с `--gtest_filter` показал, что висит Gcd;
(2) трассировка fprintf между фикстурами локализовала конкретную пару;
(3) пошаговый прогон Евклида нашёл первый расходящийся divMod.

Урок: `tail`/пайпы съедают вывод и маскируют прогресс — трассировку надо
смотреть по фильтру конкретного теста, а не по хвосту полного прогона.

## Python-порт как главный инструмент

Алгоритм над разрядами (Кнут D) переносится в Python построчно за минуты.
Это дало: точное воспроизведение бага без пересборок, пошаговое сравнение
с точной арифметикой бигинтами (un-массив против точного остатка на каждом
шаге j), и фаззинг 200k–500k случаев с bias на противные паттерны
(малые верхние разряды → большие сдвиги s; сплошные 0xFFFFFFFF).

Итог фаззинга после фиксов: 0 расхождений на 500k случаев. Соотношение
усилий: Python-итерации заняли минуты против десятков минут на
C++-пересборках.

## Уроки по самим багам

1. **Направление сдвига при денормализации остатка**: для правого сдвига
   биты приходят из разряда СВЕРХУ (`un[i+1]`), формула с `un[i-1]` —
   левый сдвиг. Баг маскировался при `s = 0` (верхний разряд делителя с
   установленным старшим битом) — половина случайных делителей его не
   видела. Вывод: покрытие должно быть осознанно смещено на граничные
   значения сдвига (s = 0, s = 31), а не только равномерно случайно.
2. **Заём в Кнуте D бывает равен 2**. Переписывание «в лоб» беззнаковой
   арифметикой с заёмом ∈ {0,1} теряет 2^32 — расхождение ровно на
   степень двойки в старших разрядах при совпадающих младших является
   сигнатурой потерянного заёма. Честная формула — ceil(deﬁcit / 2^32)
   по точному дефициту.
3. **Паддинг чанков toString**: при выдаче наборов фиксированной ширины
   выравнивается всё, кроме СТАРШЕГО чанка, а порядок порождения чанков —
   от младшего к старшему. Ошибка «первый/последний» ловится только
   тестом на конкретное число с известной строкой.

## Правило на будущее

Любой новый числовой алгоритм перед включением в C++ прогоняется
Python-портом с фаззингом ≥ 100k против встроенных бигинтов; C++-тесты
фиксируют репро крайних случаев. Property-тесты в C++ (50k итераций,
инварианты усечённого деления) — обязательный слой, они ловят регрессии,
но фаззинг с оракулом находит баги быстрее и точнее.
