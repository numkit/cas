# C1: слой алгебраических чисел и полный Трагер (старт 2026-09-06)

Цель C1 — довести рациональное ядро до 100% охвата: интеграл ЛЮБОЙ
рациональной функции, лог-часть через Rothstein–Trager без факторизации
знаменателя, вычеты — корни результанта res(A − tS′, S), т.е.
алгебраические числа.

## Дорожная карта слоя

1. ✅ Изоляция вещественных корней (poly/sturm): последовательность
   Штурма, коши-граница, изоляция бисекцией, уточнение. Тонкость,
   пойманная тестами до первого зелёного прогона: подсчёт вариаций
   знаков с пропуском нулей имеет ПОЛУОТКРЫТУЮ семантику (a, b] —
   конечные точки могут быть корнями. Изолятор несёт флаг «корень в
   hi», уточнение выбирает половину подсчётом Штурма, а не сменой
   знака (исходный p может иметь корни чётной кратности — знак меняет
   только бесквадратная часть!).
   Оракул: Durand-Kerner на Python (18 векторов), property: 3000
   случайных (дизъюнктность, ровно один корень, знакопеременность
   бесквадратной части), 2000 произведений известных рациональных
   корней (каждый изолирован).
2. ✅ `Budget` (core/budget.hpp) — отменяемость с первого дня (решение
   M0, теперь реально в коде; трединг в алгоритмы — по мере роста).
3. ✅ `Algebraic` (poly/algebraic): число = (моничный бесквадратный
   полином, изолирующий интервал); рациональные канонизированы в
   линейную форму x − r с точечным интервалом. Точное сравнение:
   сначала gcd полиномов — если оба числа лежат среди корней gcd
   (проверка счётом Штурма строго внутри интервала), сравниваем корни
   одного полинома (пересечение с одним корнем ⇒ равенство); иначе
   числа доказуемо различны — уточнение до разделения. Точные
   рациональные против открытых интервалов — через eval в точке и
   уточнение.
   Два бага пойманы тестами до коммита: (а) sign() считал 0 корнем
   числа, когда 0 — КОНЕЦ интервала (корень на границе не есть число);
   (б) refineRoot может вернуть точный интервал при попадании
   бисекции в рациональный корень — Algebraic обязан тогда
   нормализоваться в линейную форму, иначе инвариант
   «exact ⟺ рациональное» ломается и счёт Штурма получает
   вырожденный интервал (Debug-ассерт поймал).
4. ✅ Арифметика факторкольца Q[t]/(c) (poly/modcpoly) — вместо
   изначально планировавшейся полной Q̄-арифметики через результанты:
   критический путь Трагера — модульные вычисления в Q[t]/(c), а не
   поле алгебраических чисел (решение зафиксировано при планировании;
   результант уже берётся интерполяцией, см. промежуточный итог ниже).
   ModCRing: add/sub/mul/neg/inv/div по модулю неприводимого c
   (линейный c вырождается в Q — единый код); ModCPoly: плотные
   многочлены над этим полем, деление, монический gcd (Евкид).
   UPoly::invMod и operator% подняты в публичный API из ratint
   (дедупликация). Тонкость дизайна, пойманная Debug-ассертом и
   крашем в Release: безринг-ноль (default ModCPoly) обязан быть
   «нулём любого кольца» — операции обязаны брать кольцо с той
   стороны, где оно есть; ассерт в свободной функции не имел доступа
   к privates и молча выпадал в Release (NDEBUG вырезал выражение
   целиком) — проверка перенесена в private static член.
   Тесты: 30 векторов Python-оракула (два модуля: t²−2, t²+t+1;
   сложение/умножение/обратный), вырожденный линейный модуль,
   полевые аксиомы 3000 итераций (t²+1), кольцевые инварианты и
   divMod-тождество 2000 итераций, фиксированный gcd над Q(i).
5. ✅ Квадратичные вычеты через модульный Трагер (ratint): второй
   выметающий проход по результанту остатка — рациональные корни
   (включая нулевые: балластные полюса выбрасываются редукцией дроби
   по gcd числителя и знаменателя) уходят группированными логарифмами;
   если нерациональный остаток — ровно одна неприводимая квадратика
   c = t² + pt + q (для deg 2 «неприводимость ⟺ нет рационального
   корня» — факторизация не нужна), то v = gcd(A − tS′, S) над
   Q[t]/(c) через ModCPoly, коэффициенты v = A(x) + t·B(x), и пара
   сопряжённых вычетов даёт:
   - D = p²−4q > 0 (вещественная пара): α·log(A+αB) + ᾱ·log(A+ᾱB),
     α = u ± √D/2 — коэффициенты через Pow(d, 1/2), RootOf НЕ нужен;
   - D < 0 (комплексная пара): u·log(W) + √(−D)·atan(X/Y),
     X = A+uB, Y = wB, W = X²+w²B² — вещественная форма с √(−D).
   Ключевой факт: сумма по сопряжённым РАЦИОНАЛЬНА как производная —
   сертификат остаётся в Q(x), кольцо нужно только для вычисления v.
   ∫dx/(x²+2) = (√2/2)·atan(x/√2), ∫dx/(x²−2) = (√2/4)(log(x−√2) −
   log(x+√2)) — обе раньше были Unevaluated. Покрытие: ЛЮБАЯ
   квадратичная фактор-часть знаменателя с любым дискриминантом
   (DoD 2000 случайных). Пойманные до коммита баги: масштаб аргумента
   atan (2w вместо w), чтение p,q из немоничного squarefreePart,
   снапшот производной до редукции знаменателя (v вырождался в
   константу) — все по одному на каждую итерацию отладки, гейт
   каждый раз отказывался сертифицировать неверную форму.
   Полная Q̄-арифметика через результанты — отложена (Риобо/предположения).
6. ⬜ Expr: RootOf-атомы + Цассенхаус + Трагер степеней ≥ 3.
   6a. ✅ F_p[x] и факторизация над F_p (poly/fppoly): плотные
   полиномы над F_p (p < 2³¹, u64-арифметика), divMod/gcd,
   powMod с BigInt-показателем (экспоненты масштаба p^d), полная
   факторизация: бесквадратная часть → distinct-degree (x^(p^d) − x)
   → Cantor–Zassenhaus равностепенного расщепления
   ((p^d−1)/2-степени), детерминированный PRNG.
   Верификация без внешнего оракула (sympy нет): реконструкция
   произведения + ферма-критерий неприводимости каждого фактора
   (x^(p^d) ≡ x mod g и gcd(x^(p^(d/q))−x, g) = 1 для простых q|d) —
   полное доказательство корректности разложения, не зависящее от
   алгоритма. Классика: x⁵−1 mod 3, x⁷−x mod 7 (7 линейных),
   неприводимый кубик; property 500 случайных (deg ≤ 7, p ∈ {7, 101})
   и 60 собранных из известных неприводимых.
   Урок теста: факторизация монична — сравнивать с моничным
   ассоциатом бесквадратной части (ловушка: деление на lc, не на
   lc·x^deg).
   6b. ✅ Поднятие Гензеля + реконструкция → факторизация Q[t]
   (полностью закрыта в сессиях 2026-09-07/08).
   6c. ⬜ RootOf-атомы в Expr (таблица полиномов в Ctx, aux-id) +
   Трагер для неприводимых c степеней ≥ 3 (сертификат — след
   Norm/Trace в кольце).
7. ⬜ Полный Риобо: комплексно-сопряжённые пары вычетов → вещественные
   арктангенсы общего вида.

## Промежуточный итог: Трагер для рациональных вычетов (2026-09-07)

`resultantT(P, Q, M)` = res_x(P − t·Q, M) — интерполяцией по t = 0..deg M
(специализация коммутирует с результантом; deg M + 1 обычных Q[x]-результантов
+ Лагранж). Шаблонизация UPoly не понадобилась.

Лог-часть переписана: сначала Трагер — рациональные корни бесквадратной
части R(t) = res(A − tS′, S) дают ВЫЧЕТЫ; каждый вычет r даёт одну
ГРУППИРОВАННУЮ логарифму r·log(gcd(A − rS′, S)) по всем полюсам с этим
вычетом (∫(2x+3)/(x²+3x+2) = log(x²+3x+2) одной группой — ось «качество
формы»). Остаток дроби уходит в старый путь расщепления. Урок: перебор
делителей для поиска рациональных корней РЕЗУЛЬТАНТА ломается о рост
коэффициентов (deg 10 уже даёт >2^40) — поиск вычетов сделан
best-effort: бюджет исчерпан → пропустить группировку, корректность не
страдает (старый путь находит те же корни по маленьким множителям).

Тесты: тождество специализации в случайных точках, оракул вычетов
(квадратичная часть R обязана равняться ∏(t − cᵢ) по построенным
вычетам), группированные фиксированные случаи. 71 тест зелёный.

## Сессия 2026-09-07 (вечер): Цассенхаус 6b — частично, с багом

`factorPrimitiveInteger` / `factorOverQ` (poly/zassenhaus): съём
контента и знака → поиск простого p (не делит lc — ПРОВЕРКА СТЕПЕНИ
обязательна, без неё p|lc роняет степень и инвариант Гензеля ломается
молча в Release) → факторизация над F_p (FpPoly) → линейный Гензель
(пошаговый, Безу-пара над F_p НЕИЗМЕННА — факторы конгруэнтны себе
mod p на всех шагах) по бинарному дереву групп → реконструкция
подмножествами (маски по popcount) с точным делением над Z; финальный
остаток — точный целочисленный кофактор, НИКОГДА подъёмный
представитель (моничный mod-p^k представитель может не существовать
над Z — источник одного из багов). factorOverQ краткостен: Юн над Q →
бесквадратные компоненты → факторы с кратностями.

Поймано и починено по ходу (все до первого зелёного коммита):
(1) extGcd стартовые кофакторы перепутаны — инвариант sᵢa+tᵢb=rᵢ
нарушался с первого шага; изолированный тест проверял только степень
(любая константа!), теперь проверяется точное тождество s·a+t·b=1
(500 случайных пар).
(2) Реконструкция писала подъёмный g[i] как финальный «фактор».
(3) p|lc без сверки степени — Debug-ассерт «congruence invariant».
(4) Нерёдусированное произведение в ветке «остаток неприводим».

ОТКРЫТ БАГ (bugs/opened/poly/zassenhaus-cubic-cofactor-unsplit.md,
guard DISABLED_QuarticCubicSplitDisabled): 27x⁴−54x³−144x²−16x+320 —
кубический кофактор 9x³−6x²−56x−80=(3x−10)(3x²+8x+8) возвращается
целиком: подъём/реконструкция не находят расщепление при данном
распределении единиц между mod-p факторами. AssembleFromKnownFactors
property DISABLED до фикса. RandomPolynomialsReconstruct (200
случайных) и фиксированные классы зелёные — баг редкий, но реальный.
До фикса factorOverQ нельзя подключать в Трагер (вычеты будут
неминимальны, проверка неприводимости — занижена).

87 тестов зелёные (Release ~105 c), 2 DISABLED.

## Сессия 2026-09-07 (ночь): баг Цассенхауса — исходный случай починен, остался один

Диагноз исходного бага (27x⁴−54x³−144x²−16x+320): поглощение lc mod p
в ОДИН подъёмный фактор замораживает старший коэффициент произведения
— коррекции Гензеля имеют степень ниже своего фактора и никогда не
трогают старший коэффициент, поэтому при 27−2 = 25 ≢ 0 (mod 125)
конгруэнция f = ∏gᵢ (mod p^k) структурно недостижима при k ≥ 3.
Тщательное ручное прослеживание шагов (e₂ ≡ 0 — ошибка: g₀v+h₀u ≡ e
только mod 5, не над Z; тождество ограниченного решения — и его
нарушение при deg eFp = deg g + deg h) вскрыло именно эту
несовместимость.

Фикс: моничный подъём (цель — моничный ассоциат f, факторы моничны,
никакого поглощения lc) + реконструкция перебирает положительные
делители D текущего старшего коэффициента на каждое подмножество,
причём D·G редуцируется mod p^k в симметричный диапазон ДО
content-нормализации (иначе нормализация съедает масштаб и делители
вида 3x−4 не видны). Guard QuarticCubicSplit включён и зелёный.

Остался ОДИН случай (см. баг-файл, PARTIALLY FIXED):
12x⁵+106x⁴+316x³+380x²+230x+100 = 2(x²+5x+5)(2x²+x+1)(3x+10) — фактор
2x²+x+1 (дискриминант −7) теряется; p=3 делит lc, p=5 даёт коллизию
корней, p=7 — двойной корень мод p. Property AssembleFromKnownFactors
остаётся DISABLED. 88 тестов зелёные.

## Сессия 2026-09-08: Цассенхаус закрыт — корнем всех падений была ОДНА строка

Два дня «разных» багов реконструкции (квартик, квинтик, изолированный
кубик, 2+2-разбиение) свелись к одной строке: `bpMod` использовал
усечённое деление BigInt, и ОТРИЦАТЕЛЬНЫЕ коэффициенты проходили
нередуцированными (−615 оставалось −615 вместо 10 mod 625). Каждый
кандидат реконструкции, масштабированный делителем D, проходил через
bpMod; при отрицательном симметричном представлении кандидат молча
выходил из системы вычетов и никогда не совпадал с истинным
фактором. Второй фикс того же класса: контент-нормализация кандидата
— только ПОСЛЕ точного деления (до него она съедает масштаб D).

Однострочный фикс bpMod делает исходную подмножественную
реконструкцию корректной для ВСЕХ случаев, включая 2+2-разбиение
квинтика (проектировавшийся в погоне «peel-one-factor» вариант
корректен, но строго слабее — отброшен). Баг закрыт по протоколу
(bugs/closed/poly/, guard + включённый property). Урок теста: сажать
в property можно только НЕПРИВОДИМЫЕ факторы (x² законно
расщепляется Юном на x·x — это не потеря кратности).

89 тестов зелёные (Release ~105 c). 6b закрыт полностью: factorOverQ
годен для Трагера.

## Сессия 2026-09-08 (вечер): вычетный конвейер на factorOverQ + баг мульти-квадратик

Интегратор переведён с бюджетного поиска рациональных корней
результанта (лимит 2^40 бит по делителям) на ПОЛНУЮ факторизацию
Цассенхауса: оба вычетных прохода перечисляют рациональные вычеты
через factorOverQ — ничего не пропускается. Квадратичный блок
перестроен из «ровно одной квадратики остатка» в ЦИКЛ по всем
неприводимым квадратичным факторам Rsq2 (gcd над Q[t]/(c_i) захватывает
только полюса с вычетами — корнями c_i), каждый с вычитанием вклада
пары из бегущей дроби. Старый splitting-фолбэк сохранён — регрессий
нет (все 11 интеграционных тестов зелёные, включая deg-10 DoD).

ОТКРЫТ БАГ (bugs/opened/integrate/ratint-multi-quadratic-leftover.md,
guard DISABLED_MultipleQuadraticResidueFactors): знаменатель
(линейный)(квадратика)(квадратика) — после цикла остаётся
непотреблённый остаток, фолбэк отказывает «degree > 2». Одна
квадратика работает ((x²+2)(x²+3) проходит) — подозрение на
бухгалтерию вычитания между итерациями. До фикса — honest
Unevaluated; против main прогресс только положительный.

89 тестов зелёные (Release ~70 c).

## Сессия 2026-09-08 (ночь): сужение бага мульти-квадратик + фикс нулевого остатка

Точная диагностика по репро N/D, D = (x+2/3)(x²−x+3)(x²+x/4+4):
(1) интеграторная сторона НЕ при чём — квадратичный цикл вообще не
запускался: factorOverQ вернул бесквадратный результант (deg 5) ЦЕЛИКОМ;
(2) FpPoly::factor на образе mod 19 корректен (корни {3,7,8}: d1 d1 d1
d2 — изолированный тест); (3) инварианты Гензеля целы (Debug без
ассертов). Оставшийся подозреваемый — подмножественно-делительная
реконструкция factorPrimitiveInteger на этом входе (lc =
2043157708800). Следующая сессия: дамп divisorsOf(lc) и кандидатов.

Попутно починен и оставлен реальный дефект: квадратичный цикл
интегратора обязан останавливаться при обнулении бегущего числителя —
gcd(0 − tS′, S) над Q[t]/(c) бывает нетривиален, и вычитание его
вклада воскрешает нулевой числитель, порождая мусорный остаток.

89 тестов зелёные (Release ~83 c), 2 DISABLED-гарда.

## Сессия 2026-09-09: закрыт баг мульти-квадратик — снова однострочный корень

Гипотеза предыдущей сесси подтвердилась мгновенно: в подмножественной
реконструкции factorPrimitiveInteger перечисление делителей старшего
коэффициента стояло под 40-БИТОВЫМ КАПОМ (костыль ранней
реализации). lc = 2043157708800 — ровно 41 бит → список делителей
схлопывался в {1, lc}, правильные делители (3, 9, ...) не
пробовались, честный фолбэк возвращал полином целиком — вверх по
конвейеру это выглядело как «factorOverQ не фактуризует результант».
Кап снят; перечисление — чистый divisorsOf (пробное деление по
УБЫВАЮЩЕМУ кофактору, гладкие lc быстрые). Известная цена
зафиксирована: большой простой делитель P стоит sqrt(P) BigInt-делений
(Pollard-rho — если заболит). Баг закрыт по протоколу; property
MultipleQuadraticResidueFactors включён (500 случаев: две неприводимые
квадратики с несquare-дискриминантами + линейные, 100% PROVED).

ВАЖНО: после закрытия бага интегратор впервые решает знаменатели
(линейный)(квадратика)(квадратика) с любыми дискриминантами —
квадратичные вычеты покрыты полностью, без single-quadratic
