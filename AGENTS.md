# numkit-cas repo notes for AI coding agents (AGENTS.md)

## Project quick facts

- Symbolic computation core for Numkit (exact arithmetic, hash-consed
  expression DAG, symbolic integration with proof-carrying verification).
  Specification: `notes/cas-integrator-plan.md` (v0.4).
- **Integration contract is BINDING for all code** (the core is vendored into
  the Numkit tree later; see `notes/integration-model.md`):
  - C++17 strict — no C++20/23 features;
  - zero external dependencies in library code (gtest is test-only, via
    FetchContent);
  - MSVC-portable — no `__int128`, no intrinsics without a portable fallback;
  - single-threaded base, WASM-safe;
  - PMR-compatible memory (the arena layer sits on `std::pmr`).
- Header layout `include/numkit/cas/**` mirrors the future vendored
  destination inside the Numkit tree — nothing gets renamed at integration
  time.

## Build & test

```
cmake -S . -B build/msvc -G "Visual Studio 17 2022" -A x64
cmake --build build/msvc --config Release
build/msvc/tests/Release/nkcas_gtest.exe        # or: ctest --test-dir build/msvc -C Release
```

Debug build with active asserts: same commands with `build/msvc-dbg` and
`--config Debug`. The full suite is fast (< 1 s Release) — run it for every
change.

Test layers (keep all three for numeric code):
1. **Fixed oracle vectors** — generated by Python (the reference oracle),
   embedded as decimal strings; cover edge cases (2^63/2^64 boundaries,
   INT64_MIN, exact multiples, negative operands).
2. **Property tests** — randomized invariants with fixed PRNG seeds
   (division identities, algebraic laws, string round-trips, int64-range
   cross-checks). 50k iterations is the default scale.
3. **Boundary tests** — explicit documented edges.

  every future change.

## Bug protocol (`bugs/`)

- Every bug found — in new code or latent — is filed IMMEDIATELY in
  `bugs/opened/<area>/<short-name>.md`, one file per bug: description,
  exact reproduction (inputs + expected vs actual), `Kind` tag. Never
  "later".
- **Found a bug → add a GTest guard** in `tests/`. If the fix does not land
  in the same change, prefix the test with `DISABLED_` so the green baseline
  stays green but the guard is real.
- **Fixed a bug → move the file** `git mv bugs/opened/<area>/x.md
  bugs/closed/<area>/`, record the commit hash and the guarding test name in
  it, and remove the `DISABLED_` prefix.
- File template and tags: `bugs/README.md`.

## Clean code rule

- Only clean code: no crutches, no workaround bridges, no dirty hacks —
  root-cause fixes. A genuinely temporary bridge needs a filed bug id and
  dies when that bug closes.
- Cleanliness includes portability: no UB, no implementation-defined
  arithmetic on signed values, no unreachable-platform assumptions.
